# Мінілабораторна №1: Count Even Numbers (C++17)

## Мета

Реалізувати невелику консольну програму на C++17, яка рахує кількість **парних цілих чисел** на відрізку **[left, right] включно**. Це окреме демонстраційне завдання для тестування AI Lab Grader, **не частина методички про інтеграли**.

## 1. Вимоги до програми

- Назва виконуваного файлу: `count_even` (у Windows допустимо `count_even.exe`).
- Інтерфейс: `count_even <left> <right>` — **рівно два** аргументи командного рядка.
- Обидва аргументи — десяткові цілі числа в діапазоні від `-1000` до `1000` включно.
- Має виконуватися `left <= right`.
- Парне число — це ціле `n`, для якого `n % 2 == 0`. **Нуль і від'ємні парні числа також рахуються.**
- За успіху вивести **лише одну цілу кількість** у `stdout`, після неї `\n`. У `stdout` не повинно бути іншого тексту.

### Приклади

```text
$ ./count_even 1 5
2
$ ./count_even -3 3
3
$ ./count_even 0 0
1
```

## 2. Помилки та exit codes

| Ситуація | Exit code | Вивід |
|---|---:|---|
| Успіх | `0` | Лише результат у `stdout` |
| Кількість аргументів не дорівнює двом | `1` | Зрозуміле повідомлення у `stderr` |
| Некоректне число, число поза `[-1000, 1000]`, або `left > right` | `2` | Зрозуміле повідомлення у `stderr` |

У разі помилки `stdout` має бути порожнім. Інтерактивне введення заборонено.

## 3. Компіляція й здача

- Мова: C++17 (або новіша, але обов'язково сумісна з C++17).
- Потрібні `main.cpp` і `CMakeLists.txt`, який створює executable `count_even`.
- Проєкт має компілюватися стандартним способом:

```bash
cmake -S . -B build
cmake --build build
./build/count_even -3 3
```

- Сторонніх бібліотек не потрібно.

## 4. Критерії оцінювання (5 балів)

| Критерій | Бали | Що перевіряємо |
|---|---:|---|
| Збірка | 1 | CMake створює `count_even` без помилок |
| Коректність | 2 | Правильний результат, включні межі, нуль і від'ємні значення |
| Валідація CLI | 1 | Правильні exit codes і повідомлення для поганих аргументів |
| Формат виводу | 1 | Тільки одне число та newline у stdout за успіху; stderr на помилках |

**Важливо для AI-рецензента:** якщо програма не компілюється, не стверджуй, що runtime-тести пройдені. Вказуй, що саме перевірено, а що недоступно. Кожне зауваження має посилатися на код або відтворюваний запуск. Не вигадуй балів за додаткові критерії.

## 5. Мінімальна послідовність перевірки

1. Ознайомитися з кодом, не довіряти коментарям і README замість реальної перевірки.
2. Скомпілювати через CMake.
3. Якщо збірка успішна — перевірити пару позитивних і від'ємних меж, включність правої межі, `0`, поганий argc і некоректні числа.
4. Записати конкретні результати перевірок та фінальну оцінку за рубрикою.

Для демонстрації достатньо **однієї** збірки і короткого набору запусків; не потрібно санітайзерів, Valgrind, PVS-Studio, бенчмарків або великих тестових фреймворків. Запуск студентських ZIP здійснювати лише у контрольованому ізольованому середовищі.
